## How I build

1. Clarify the workflow, roles, data definitions, and acceptance criteria.
2. Turn the rules into small, testable interfaces and visible system states.
3. Verify the real path with synthetic data, then document what was tested and what remains environment-specific.

The public repositories use synthetic or redacted examples. Production credentials, customer data, private vendor materials, and deployment secrets stay outside the repositories.

## Open source

The repositories here are organized as independent projects. Issues and pull requests are welcome when they include a focused change, reproducible steps, and the checks that were actually run.
